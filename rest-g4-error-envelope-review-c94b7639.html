Findings

F1 — Blocking: exact error bytes depend on undefined resource-label literals

R4c and the wire companion require every error to copy the route's exact success-envelope resource value. The spec gives literal values only for assignments and execution map. R2 and R3 enumerate many other routes, while R7 uses human resource names without stating that those table labels are the encoded envelope strings.

Two confident implementations can therefore differ. For GET /api/facts, one can encode "facts" from the R7 row, while another can encode "condition facts" from R8's statement that this is the exact firehose resource for the same resource. Similar ambiguity exists for /api/catalog/harnesses, transcript messages, coordination share, work-item trace, and digest members. Both implementations satisfy the current cross-reference, but their exact error bytes differ. That violates the G4 goal and makes A35 undecidable for the full route surface.

Evidence: rest-state-api-v1.md:128-130,201-203,288-300,309-370,386-390,436-442,683-723,859-862,1474-1481; rest-state-api-v1-wire-schema.md:92-111.

Deletion test: deleting resource from generic errors would remove the ambiguity, but it would break the preserved ExecutionMap bytes and the commissioned envelope. Acceptance as a named failure would defeat deterministic client decoding. A closed route-to-resource-label mapping is therefore the smallest viable closure.

F2 — Important: spec homing names both a two-file and three-file review set

The G4 header and the inserted homing clause say the exact candidate set is the main REST spec plus its wire companion. The same homing section then says “This amendment” remains a candidate until one exact revision of its three-file canonical set passes review and lands. A reviewer or lander can reasonably treat either statement as controlling, so the required custody/review boundary is not decidable from the document.

Evidence: rest-state-api-v1.md:3-10,103-120.

Deletion test: deletion or precise qualification of the stale three-file sentence closes this finding. Adding another lifecycle mechanism is unnecessary.
