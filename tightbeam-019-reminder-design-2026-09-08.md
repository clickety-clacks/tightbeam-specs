# 0.1.9 reminder implementation design basis

8 September 2026. Lead-selected design basis for existing R1 after reading the four attributed designer receipts below and Morrow's bounded protocol review. This is authorization to carry the selected behavior through the existing delivery owner, not source verification or release acceptance. Numeric behavior remains governed by `tightbeam-019-reminder-policy-2026-09-08.md`.

## Selected implementation boundary

Use one nullable versioned reminderState value on the existing assignment, rather than a second obligation registry or delivery queue. Persist successful notification identity/time and the relevant evidence/consequence snapshot, next eligibility/backoff, and pending wake claim/epoch. Old rows with null state retain first-notice eligibility and existing reassessment. Keep existing qualified-wait, bounded-checkpoint and effort policy intact.

Reuse the condition-fact path for an explicitly attributed consequence tied to the assignment. Validate the accountable issuer and a stable consequence key, revision and attention-request identity. Replaying or republishing the same request cannot reset backoff; a deliberate new owner attention request can. The producer must supply the supported command/API input and projection needed to use this contract. A design that relies on payload fields no authorized agent can submit does not meet acceptance. Do not infer semantic change from prose.

Enqueue the existing durable wake and its immutable pending snapshot atomically. Advance backoff only from the authoritative delivered consumer-turn terminal correlated to the matching wake, claim epoch and assignment. Enqueue, fired, queued and running are not successful-notice evidence. Make terminal processing idempotent across restart and repeated callbacks. Recovery must fence successor rebinding against late predecessor results. Unknown external outcomes remain subject to reconciliation; at-most-once state advancement is not exactly-once external delivery.

A later consequence stays eligible after an older pending notice succeeds. Required effort decisions retain their existing authority and deadlines outside the ordinary-reminder throttle. The designer's detailed sequences below are acceptance obligations for the implementation.
