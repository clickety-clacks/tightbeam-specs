# Substrate-native exec desks — v1

Status: DRAFT FOR INDEPENDENT REVIEW. Authority: `wi_795a354d-3f97-4805-b472-b637c7542d54`, Mike's 2026-08-26 brief and revisions. Canonical home: repository `clickety-clacks/tightbeam-specs`, path `substrate-native-exec-desks-v1.md`; the work item binds the reviewed content hash after review and elects no product target. This specification supersedes the earlier desk-topology recommendation only for inbound delivery mediation.

## Goal

Make mediation of each inbound worker message a delivery-physics guarantee. A caller continues to address the worker through existing `wake` and `dispatch` seams. Tightbeam accepts the send only after it durably creates an inbound mediation record for that worker's desk. The desk then acts as the worker's agent under org-authored policy: it can spend less worker attention without deleting message information or deciding the worker's work.

The first pilot is one desk for Main. It measures the attention cost and outcome distribution before an org chooses more layers.

## Non-Goals

- V1 does not mediate worker outbound traffic. Outbound mediation is a successor.
- V1 does not add a desk address, ACP session, workdir, shell, repository, filesystem, or assignment to a desk. The narrow worker-transcript read required by `OBSERVE/DIGEST` is the sole exception to the desk's row-only material boundary.
- V1 does not answer a sender from rows. Mike struck `answer-from-rows`.
- V1 does not make `verify-prods` a separate action. A desk may annotate a delivered claim with cited rows.
- V1 does not absorb `wi_1100e078`. That independent notice-layer batcher remains related prior art and must compose with desk summarization.
- V1 does not implement, deploy, release, target a line, or alter 0.1.x behavior.

## Terms

- **Worker**: an ordinary addressable Tightbeam session. Existing `wake` and `dispatch` target this identity.
- **Desk**: a lightweight Tightbeam-native agent bound to one worker's inbound path. It reads and writes only durable rows. It has no desk binding of its own.
- **Inbound envelope**: the durable record made for one accepted worker-addressed inbound send before a desk acts.
- **Mediation record**: the append-only row that links an envelope, desk, policy revision, action, outcome, source rows, cause, and acting principals.
- **Delivery policy**: a globally selected default plus an org override. It supplies desk judgment context; it does not give the substrate opinions.
- **Class hint**: the sender's `wake --class` election. It is evidence to the desk and never selects the action by itself.
- **SUMMARIZE**: desk inference that semantically collapses an already mechanically batched set into one worker delivery. It never creates, schedules, or owns the batch. Deduplication and stale-expiry are SUMMARIZE cases with an explicit record, not separate verbs.
- **ANNOTATE**: desk inference that delivers a claim to the worker and may attach durable row facts. With no attached facts it is the explicit delivered-claim path; it still is not a separate pass-through verb.
- **ESCALATE**: desk inference that forwards context to an already-addressable authority worker. That target's normal desk mediation then applies.
- **Effective parent**: the worker resolved by the shared `effective_parent` helper defined by `wi_cd2bb06d`. It returns `operationalParent` when set; otherwise it returns the owner principal's Main. Desk code does not duplicate this fallback.
- **OBSERVE/DIGEST**: the fourth v1 desk capability. It reads only its worker's transcript window and creates or supersedes a standing activity-summary `NOTE` row. It is not a mediation action and cannot answer a question, decide work, or create a worker turn.
- **Activity-summary NOTE**: a knowledge row under knowledge-row law. It reports sourced observation without authority and carries the worker identity, performing desk identity, covered transcript window, observed-at time, source references, interval, and explicit `supersedesNoteId` when it replaces a prior summary.
- **Activity-summary authority**: the existing knowledge-row read authorization evaluated for a requesting caller or system principal and worker scope. It gates an observation request, its cancellation, and the resulting NOTE; it grants the principal no worker-transcript access.
- **Observation request**: an append-only row created by the worker-addressed `activity-summary` read seam or by a worker-turn-completion or check-in-arrival event. It names the worker, requesting caller or system principal, active desk binding and version, covered interval, cause event, idempotency key, due time, absolute deadline, execution-wake id, nullable observation-model-execution id, and request state; it never addresses a desk or creates a worker turn.
- **Observation cancellation event**: an immediately due observation-cancellation execution wake for one accepted observation request. It records cause `requester_cancelled`, the observation request, worker, initiating principal, acceptance-time authority decision and revision, idempotency key, due time, and state; it never addresses a desk or creates a worker turn.
- **Observation model execution**: bounded semantic work keyed by one observation request. Its immutable input names the worker, desk, binding version, bounded transcript entries and source references, policy revision, schema revision, deadline, attempt cap, and idempotency key. Its output object contains exactly `summaryText` and `citedSourceRefs`; it cannot select a mediation action or control work.
- **Event shell**: the deterministic, restart-safe desk execution layer. It reacts only to durable message-arrival, worker-turn-completion, check-in-arrival, and execution-wake events. It classifies configured facts, deduplicates, appends to the independent mechanical batch, returns stored digest or NOTE pointers, stages observation-model inputs, and validates observation-model outputs without composing semantic prose.
- **Execution wake**: a durable self-scheduled wake for a batch deadline, observation deadline, semantic-lease expiry, semantic retry, or observation cancellation. Its idempotency key, due time, and target desk are rows, so restart does not require polling or recreate a prior effect.
- **Desk failure**: an unavailable, unauthenticated, misbound, terminal, or deadline-expired desk execution. It is never a direct-delivery bypass.

## Assumptions

1. The direct model-provider lane can invoke an elected desk model with a provider credential scoped to the org, not copied from the worker's harness home.
2. The existing wake/dispatch acceptance transaction can atomically persist an envelope or return a named refusal.
3. The live message database can be queried read-only for the seven-day classification analysis.
4. The reported seven-day baseline is accurate enough to seed the pilot: 27,275 inbound turns; agent-to-agent 54%, effort check-ins 19%, progress prods 11%, other process notices 8%, and user messages 4%. Data Package 2 is received on the parent assignment as `att_47a01848`.
5. `art_1e1d0b79` defines the visitor-attribution pattern required here: a desk action names both the worker it represents and the desk that performed it.
6. Mike intermediary ledger `art_a4f39376` is receiving-end evidence: of 201 Main adjudication signals, approximately all were effort check-ins; 150 were `continue`, 31 were `dismiss`, and none was a true decision. The ten highest-volume standing or coordination cards generated roughly half of the signals, and 31 signals targeted assignments already closed.

## Invariants

1. **Worker-addressed, exec-delivered.** The public send wire accepts a worker target only. No public verb, public row reference, or public retry accepts a desk as a recipient.
2. **Mandatory mediation.** For each accepted inbound send, the acceptance transaction creates exactly one envelope linked to the addressed worker's active desk binding. If no valid binding exists, the command refuses at send time with the named desk condition and creates no worker turn.
3. **Conservation.** Each envelope has exactly one terminal mediation outcome: `delivered`, `escalated`, or `expired_with_reason`. Each terminal outcome has a mediation record. No operation silently discards an envelope.
4. **Action floor.** A desk chooses only `SUMMARIZE`, `ANNOTATE`, or `ESCALATE`. `ANNOTATE` always results in delivery. `SUMMARIZE` either results in one delivery containing all member references or records each expired member's reason. `ESCALATE` names the authority worker and its resulting envelope.
5. **Two-name attribution.** A desk-authored row or delivery records `onBehalfOfWorker` and `performedByDesk`. It never claims the worker performed the desk's action.
6. **No desk authority over work.** A desk cannot file progress, completion, surrender, a product verdict, or an operator ruling; it cannot mutate work-item, assignment, decision-request, identity, credential, or target state.
7. **Policy belongs to the org.** The substrate routes envelopes, validates row shapes, and records outcomes. A desk model applies the elected policy. Global and org policy revisions are immutable, addressable, and included in each decision record.
8. **Bounded and recoverable.** A pending envelope has a recorded deadline. The semantic-lease acquisition transaction arms one durable lease-expiry execution wake due no later than that envelope deadline. Each recovery transition preserves a due execution wake until a new lease or terminal outcome commits. A crash, timeout, cancellation, or provider failure produces a durable named failure and a lawful retry or expiry outcome; it never produces a hidden hold.
9. **Topology is emergent.** Each worker has one inbound desk binding. An org may form further layers only by policy escalation to another worker; desks remain unaddressable and deskless, so recursion terminates.
10. **Privacy and least material.** Prompt assembly reads only the envelope, cited durable rows, current policy, and explicitly authorized worker metadata. `OBSERVE/DIGEST` may additionally read only its bound worker's transcript window to derive the activity-summary NOTE. The activity-summary authority gates each request, cancellation, and NOTE read without exposing that transcript to the caller. Neither path reads a workdir, harness credential store, another worker transcript, or unrelated row content.
11. **Observation is not authority.** `OBSERVE/DIGEST` publishes a sourced NOTE, never an attest, verdict, lifecycle claim, answer, or control action. Each replacement names the prior note it supersedes. An empty observed window states `no activity since <window-start>`.
12. **Debounce is bounded observation.** A desk recomputes at most one activity-summary NOTE in each policy-configured `N`-minute interval, independent of the count of effort check-ins or other inbound traffic. A check-in receives the current NOTE id or link and no newly composed activity prose.
13. **One parent resolution.** Any desk action that needs the worker's operational parent calls the `wi_cd2bb06d` effective-parent helper. A null `operationalParent` resolves to the owner principal's Main through that helper; the desk does not store, infer, or implement another fallback.
14. **Event-driven execution.** A desk never polls. Only a durable message-arrival, worker-turn-completion, check-in-arrival, or execution-wake event may create or execute work. Without a current event, the desk performs no database scan or model call and creates no new wake; an event-caused future wake remains inert until its due time.
15. **Two-layer execution.** The event shell performs only deterministic classification, deduplication, independent-batch append, annotation with configured row facts, stored digest/NOTE-pointer replies, observation-input staging, and observation-output validation. A model call performs semantic `SUMMARIZE` or `ESCALATE` judgment or composes an `OBSERVE/DIGEST` activity summary. Model cost therefore scales with debounced semantic work, not inbound traffic volume.
16. **Receiving-end evidence.** An effort check-in aimed at a closed assignment or covered by a standing digest/NOTE is resolved in the deterministic event shell with cited row facts or a stored pointer. It cannot trigger a semantic-model call merely because it arrives. `art_a4f39376` is the initial receiving-end evidence for this floor.

## Architecture

### A. Binding and send transaction

`desk_bindings` records `workerSessionKey`, `deskId`, `state`, `policyRevision`, `boundAt`, `boundBy`, and a row version. The system provisions a binding for each active worker before that worker accepts inbound traffic. A desk has no `desk_bindings` row as worker.

For a worker-addressed `wake` or `dispatch`, the delivery transaction reads the active binding and, in the same transaction, either:

1. inserts an `inbound_envelope` with stable `envelopeId`, source verb/id, worker identity, sender identity, prompt reference, class hint, ordering key, deadline, and idempotency key; then returns accepted, or
2. refuses with `desk_unavailable`, `desk_misbound`, or another typed condition required by sibling `wi_c01e8f20`.

The transaction does not create a worker turn directly. An identical accepted command reuses its idempotency key and returns the original envelope; a conflicting reuse refuses. This is the selected closure because deleting mediation defeats the delivery-physics goal, and accepting an unmediated send makes loss silent.

### B. Event-driven two-layer execution and durable lifecycle

An accepted message arrival creates an envelope execution event. The event shell claims its envelope by compare-and-swap and evaluates the configured structural policy without a model. It either delivers the source prompt (`ANNOTATE` with zero facts), attaches configured row facts (`ANNOTATE`), invokes the independent `wi_1100e078` mechanical-batch append, returns a stored digest/NOTE pointer, or queues a bounded semantic-model decision. `pass-through` and `batch` describe those deterministic paths; they are not additional desk inference verbs. Lease-expiry wakes create recovery events only; Section C defines observation events.

The desk service leases only an envelope that needs semantic-model work. Its lifecycle is `pending -> leased -> (pending | terminal)`; a lease has `leaseId`, holder desk, and expiry. The lease expiry is the earlier of the policy lease limit and the envelope's absolute deadline. The lease-acquisition transaction also inserts one lease-expiry execution wake keyed by `deskId`, `envelopeId`, and `leaseId`, due at that lease's expiry. If the transaction cannot persist both rows, it persists neither and leaves the envelope pending. Only the current lease winner or the recovery compare-and-swap defined below may write a terminal record.

When a lease-expiry wake fires, the event shell compares the wake's lease id with the envelope's current lease in one transaction. If that lease is still current, non-terminal, and expired before the envelope deadline, the transaction records `lease_expired`, releases the same envelope to `pending`, inserts one immediately due semantic-retry execution wake keyed by the expired lease, and settles the expiry wake. If any part fails, no part commits. If the envelope deadline has arrived, the transaction records `expired_with_reason` with cause `envelope_deadline_expired` and settles the wake without reoffering the envelope. If a terminal execution or a replacement lease already won, the transaction settles the stale wake without changing the envelope. A later provider result for the expired lease fails the lease-id comparison and writes no delivery.

When the semantic-retry wake fires, one compare-and-swap either acquires a new lease, inserts that lease's expiry wake, and settles the retry wake, or records `expired_with_reason` with cause `envelope_deadline_expired` or `attempt_cap_exhausted` when that bound has arrived. If another lease or a terminal result already won, the transaction settles the stale retry wake without changing the envelope. Durable wake recovery replays the unsettled expiry or retry wake after restart; it never scans for dead leases and never creates a second worker delivery.

This lease-expiry wake is necessary because deleting lease recovery or accepting a permanently leased envelope would violate the bounded-recovery invariant.

The desk reads a fixed row API: envelope, source wake/dispatch, cited work and attests, policy revision, and prior mediation records. It writes only mediation records, desk execution records, and delivery attempts. The mediation API exposes exactly `summarize`, `annotate`, and `escalate`; no API exists for answer-from-rows or work-state mutation.

`SUMMARIZE` consumes an ordered, mechanically batched source set. It preserves each source envelope id, sender, source row, class hint, and original ordering key. It may replace repetitive content with a semantic summary, such as “three are-you-awake messages,” but the worker can query every member row. It does not select members, create a group, set a batch deadline, or schedule a delivery. The independent batcher owns the mechanical append and its deadline; it records the deadline as an execution wake, and its durable idempotency key prevents duplicate materialization after restart. `ANNOTATE` delivers the source prompt unchanged and attaches zero or more cited row facts; for example, it can put the contradicting attest beside a false no-filing prod. `ESCALATE` writes its context record and creates an ordinary worker-addressed envelope for the chosen authority worker; it never invokes a desk endpoint. When policy selects the operational-parent route, it obtains that worker only through the `wi_cd2bb06d` effective-parent helper; an explicit org policy destination remains a policy choice, not a second parent-resolution implementation.

An envelope becomes `expired_with_reason` only when its immutable deadline passes, its policy attempt cap is exhausted, or policy identifies it as a stale duplicate. The terminal row names the policy revision, evidence rows, cause, and desk principal. Expiry preserves the source envelope and emits an observable worker-facing notice on the next eligible mediated delivery.

### C. OBSERVE/DIGEST standing summary

`OBSERVE/DIGEST` is a worker-addressed read capability, not a fourth delivery action. The public `activity-summary` seam accepts a worker session or role target and rejects a desk target. The substrate applies activity-summary authority, resolves the worker's active desk binding, and then acts atomically: if a standing NOTE remains inside the debounce interval, it returns that NOTE without a new row; otherwise it inserts or reuses one idempotent observation request plus one immediately due observation execution wake for the worker and interval. The request's absolute deadline is its due time plus the policy observation-execution limit. If the transaction cannot persist both rows, it persists neither. An unauthorized request writes no observation row and reads no transcript. A missing or invalid binding refuses with the same named binding condition used by inbound mediation and creates no worker turn.

Worker-turn completion and check-in arrival are the only automatic observation triggers. In the trigger transaction, the event shell inserts or reuses one observation request and one observation execution wake keyed by worker and debounce interval. If the current NOTE is already eligible for replacement, the wake is due immediately. If the NOTE remains inside `N`, the wake is due at the NOTE's recorded `nextEligibleAt`; the request deadline is that due time plus the policy observation-execution limit. Repeated trigger events reuse the same request and wake. A check-in receives the current NOTE pointer immediately, and neither trigger creates a worker turn. Publishing a NOTE never creates its successor request or wake. With no public `activity-summary` request, worker-turn completion, or check-in arrival, the desk has no observation request, wake, transcript read, or model execution to perform.

When an observation wake becomes due, the event shell claims the request by idempotency key. For a worker with no prior NOTE, the first request uses the bounded window from `triggerAt - N` through `triggerAt`, where `triggerAt` is the public acceptance time or automatic event time. A later request uses the previous published window endpoint through its recorded observation time. Before reading the transcript, the shell compares the request's binding version with the active binding and rechecks the requesting caller or system principal's activity-summary authority. A failed check settles the request and wake with a typed refusal and reads no transcript.

For a valid request, the shell reads only the bound worker's bounded transcript window and writes one immutable observation-model input. The same transaction inserts or reuses one `observation_model_execution` in `pending` state with `observationRequestId`, `deskId`, worker identity, binding version, bounded transcript entries and source references, policy revision, activity-summary schema revision, absolute deadline, attempt cap, credential capability reference, and idempotency key. If either insert fails, neither commits and the observation wake remains unsettled. The shell does not compose summary prose.

The observation model consumes that fixed input and returns an object with exactly `summaryText` and `citedSourceRefs` under the elected schema. It cannot emit `SUMMARIZE`, `ANNOTATE`, `ESCALATE`, a work mutation, a health claim, or another control result. The deterministic validator fixes the worker, desk, window, policy, and schema from the input, requires each cited reference to belong to the immutable source-reference set, and refuses any unsupported field or reference as `observation_model_response_invalid` with a raw-response reference. That refusal consumes one attempt and follows the retriable-failure path only while both the observation deadline and attempt cap permit another attempt.

An observation model execution uses `pending -> leased -> (pending | terminal)`. Its lease-acquisition transaction inserts one expiry wake keyed by `deskId`, `observationRequestId`, execution id, and lease id, due at the earlier of the policy lease limit and observation deadline. If it cannot persist both the lease and wake, it persists neither and leaves the execution pending. Lease expiry before the deadline records `observation_lease_expired`, returns the same execution to `pending`, and atomically inserts one immediately due semantic-retry wake. A retry wake acquires one new lease plus its expiry wake or records terminal `observation_deadline_expired` or `observation_attempt_cap_exhausted`. A stale wake settles against current row state. A late provider result fails the lease-id comparison and writes no NOTE. Restart replays an unsettled expiry, retry, or observation-cancellation execution wake without a scan or duplicate model execution.

The activity-summary wire accepts a cancellation request only for an existing `observationRequestId` and the same worker target. The authorized cancellation principal is exactly the requesting caller or system principal stored on that observation request. In one acceptance transaction, the substrate requires the authenticated initiating principal to equal that stored principal and to hold current activity-summary authority for the worker. If either check fails, it refuses `observation_cancellation_unauthorized` before inserting a cancellation event or changing observation state. If both pass, the transaction inserts or reuses one immediately due observation-cancellation execution wake with cause `requester_cancelled`; an identical idempotency retry returns that event, while a conflicting reuse refuses without changing it.

When the observation-cancellation execution wake runs, the event shell repeats the principal-equality and activity-summary-authority checks and records the execution-time authority decision and revision. If either check now fails, it settles only the cancellation event as `observation_cancellation_unauthorized`; the observation request, model execution, observation wake, and NOTE path remain unchanged, and no provider cancellation is requested. If both pass, cancellation and a valid provider result compete through the existing terminal compare-and-swap. A cancellation winner records `observation_cancelled` with cause `requester_cancelled`, the initiating principal, both authority decision references, and the cancellation-event id; it settles the model execution, observation request, observation wake, and cancellation event and writes no NOTE. Only after that transaction commits does the service request provider cancellation. A provider winner publishes at most one NOTE and causes the cancellation event to settle stale without changing the terminal result.

After a valid model result, the publication transaction repeats the binding-version and activity-summary-authority comparisons. If either comparison fails, it writes no NOTE and settles the request, its observation wake, and the model execution with a typed refusal. Otherwise, the same transaction writes one activity-summary NOTE and settles those three rows. If any part fails, no part commits. The NOTE names `onBehalfOfWorker`, `performedByDesk`, transcript-window bounds, source references, observation time, policy revision, schema revision, its superseded prior NOTE, and `nextEligibleAt`; it names no future execution wake. If the configured presentation also renders a file, the NOTE stores that artifact reference; the NOTE remains the canonical query result.

A terminal observation-model failure records its named cause, attempt evidence, and raw-response reference when one exists; it settles the model execution, observation request, and wake and writes no NOTE. Retriable failure preserves the durable execution and its due recovery wake. This observation-request and semantic-execution seam is necessary because deleting the initial request loses the visible-wedge capability, while accepting substrate-authored prose violates the deterministic-shell boundary. The event-caused debounce wake is necessary because deleting it loses recomputation after a permitted trigger, while accepting NOTE-publication succession violates zero-cost idle execution.

The configured interval `N` is an org-policy value. Before `nextEligibleAt`, the desk returns the standing NOTE id without reading the transcript or composing new prose. A permitted trigger event arms the one debounce wake for that interval; NOTE publication itself arms none. If the transcript window has no activity, the model output says `no activity since <window-start>` and cannot substitute reassuring language, infer a cause, or claim that the worker is healthy. A gateway or desk restart resumes only unsettled request and execution rows; it does not poll transcript state.

Effort check-ins receive only the standing NOTE pointer. The target patrol state invokes the worker-addressed `activity-summary` read seam and reads the resulting NOTE directly; it sends no check-in message and creates no worker turn. A query after `N` creates one bounded observation request. The resulting NOTE exposes the lack of transcript activity for phantom-turn sequences 69089–69110 and the turn-73066 hang specimen instead of letting repeated prods consume worker attention.

### D. Policy and data loop

Policy has a global default and optional org override. A policy revision defines model/effort election, allowed source-row scopes, action prompts, deadline values, ordering rules, escalation destinations, and measurement cohort. A worker can publish standing instructions within that revision's schema; those instructions constrain its own desk, not other workers.

The initial taxonomy is data-derived. A reproducible read-only query over the real message database must record its query text/version, UTC window, classification rules, denominators, exclusions, and result rows. Mike's seven-day seed corpus is 27,275 inbound turns: agent-to-agent 54%, effort check-ins 19%, progress prods 11%, other process notices 8%, and user messages 4%. It found same-class recipient floods above ten per day in 80% of agent messages and 93% of effort check-ins: 261 agent-message and 102 check-in session-day floods, led by product owners, orchestrators, and watchdogs. The pilot targets those flood classes first.

Data Package 2 (`att_47a01848`) requires outcome-based taxonomy, not volume alone. The same analysis measures the worker's revealed material response as an attest inside the receiving turn window, then response-by-message and response-by-wake to correct the known undercount. Its initial reported outcome floors are: new assignments 74% of 283 turns, other process notices 61% of 4,588, agent messages 44% of 13,336, user messages 42% of 976, effort check-ins 28% of 4,881, and slate-clear notices 0.2% of 417. The report must state that attest-in-window omits valid later and non-attest responses; it therefore understates materiality, especially for agent messages. These figures are design evidence, not substrate thresholds.

The desk's own mediation rows feed a rerunnable read-only analysis. A policy revision may change only after an accountable org actor records the evidence and the new revision. The policy may use near-zero-material classes as candidates for semantic `SUMMARIZE` after independent mechanical batching, high-material classes for immediate `ANNOTATE` delivery with zero or more facts, and boundary classes for `ANNOTATE` after their independent batch is available. It never makes a volume threshold a substrate outcome rule or gives the desk ownership of a batch.

Receiving-end analysis complements the inbound corpus query. It records the receiving worker, action or disposition, assignment state at arrival, source class, standing-card identity, and whether a model was called. The first evidence is `art_a4f39376`: 201 Main adjudication signals were approximately all effort check-ins; 150 resolved `continue`, 31 `dismiss`, no true decision appeared, the top ten standing or coordination cards produced about half of the volume, and 31 signals addressed closed assignments. The analysis uses these as a reproducible cohort, not a hardcoded table: the deterministic shell targets closed-assignment and standing-card traffic for cited row/pointer handling, while a model call remains justified only by unresolved semantic summary or escalation work.

### E. Direct model-provider lane

Desk inference uses a direct model-provider request, not ACP and not the worker harness. Credential references are capability handles owned by the credential subsystem; prompts and logs never contain secret values. Mediation prompt assembly includes the fixed desk contract, current policy, envelope, permitted citations, and an output schema that can express only semantic `SUMMARIZE` or `ESCALATE`. Observation prompt assembly includes only the immutable observation-model input and the activity-summary output schema defined in Section C. Deterministic `ANNOTATE`, pass-through, deduplication, batch append, pointer replies, observation-input staging, and observation-output validation never invoke a model. Provider requests carry `deskId`, `workKind` (`mediation` or `observation`), `workId` (`envelopeId` or `observationRequestId`), policy revision, schema revision, deadline, cancellation token, and idempotency key.

Lachesis records input tokens, output tokens, provider/model, attempt id, elapsed duration, work kind, and terminal result against the desk execution. It records an unavailable quota, provider rejection, malformed response, deadline expiry, cancellation, and transport failure as distinct durable causes. Each retry state machine has an absolute work deadline and an explicit attempt cap from policy; a retry cannot outlive either. Authorized observation cancellation first records the terminal cancellation race winner and its `requester_cancelled` cause, then requests provider cancellation. This closes the turn-73066 hang lesson: a stuck mediation or observation call is observable, bounded, and cannot leave a lease without a terminal or recoverable state.

### F. Ordering, batching, and compatibility

For one worker, a mechanically batched source set retains its smallest member ordering key. A later ready set cannot be delivered ahead of an earlier ready set. A not-ready earlier set may not block an urgent ready set past that urgent set's deadline; the policy must record the ordering exception and its cause. `wi_1100e078` is related prior art only: its independent notice-layer batcher may mechanically combine notice turns before desk ingress, and desk summarization then operates over the resulting source references. Neither system creates, schedules, alters, or owns the other's batching rows; either can ship or roll back without changing the other's acceptance contract.

Legacy inbound rows remain readable. Migration creates a desk binding before enabling mandatory mediation or `activity-summary` requests for a worker and backfills no historical envelope or observation request. A rollout flag selects an explicit worker cohort. Rollback stops new cohort admission only after it records each pending envelope's chosen recovery path and preserves each live mediation or observation lease-expiry, semantic-retry, or observation-cancellation execution wake until its named compare-and-swap settles. Rollback creates no successor observation wake after a NOTE and never reroutes new sends directly to workers. Compatibility clients keep using worker targets and receive the same accepted/refused response shape plus optional envelope metadata.

### G. Wire, observability, and pilot

The send response adds `envelopeId` when accepted. The worker-addressed CLI form is `tightbeam activity-summary (--session <workerKey> | --role <workerRole>)`; its wire request carries the same worker target, caller principal, and idempotency key. Its response returns a current `noteId` or an accepted `observationRequestId`; it never returns a desk address or creates a worker turn. The same activity-summary wire accepts an observation cancellation by worker target, `observationRequestId`, authenticated initiating principal, and idempotency key. Reads expose envelope state, mediation records, terminal cause, policy revision, two-name attribution, linked source rows, observation-request state, observation-model-execution state, cancellation-event cause, principal and authority decisions, and execution-wake state to authorized readers. The public wire rejects a `deskId` target with `desk_unaddressable`. Metrics and read-only reports expose accepted/refused sends, action/outcome counts, deadlines, lease-expiry wake outcomes, observation requests, observation cancellations and refusals, observation-model attempts and causes, retries, duplicate collapses, direct-model cost, and worker-turn savings; no metric is used to decide a message outcome.

This feature teaches one new everyday agent pattern, so implementation must land one always-on substrate-manual amendment in the same release as the command. The directive tells an agent to target the worker, use `activity-summary` instead of a check-in message when it needs recent activity, follow an accepted `observationRequestId` to the resulting NOTE, and never target a desk. The manual must state the authorization boundary, the possible stale-NOTE response inside `N`, and the no-worker-turn behavior. It must not advertise the command before the command exists, and no archetype or skill may duplicate this operating rule.

The Main-first pilot records a before and after window. It cites the observed Main question queued behind 39 check-ins, the Shrdlu no-desks e2e result, and phantom/hang wedges as motivating specimens. Success is evidence, not an automatic topology decision: the report compares worker turns, delay, loss/refusal causes, policy drift, and Lachesis cost. An org actor decides whether to extend desks.

## Open Questions

- **BLOCKING — delivery destination seam.** Which existing durable turn/queue row receives a desk-produced worker delivery, and which transaction owns its atomic commit with a mediation terminal record? The spec requires one answer before implementation because a split commit could violate conservation.
- **BLOCKING — credential authority.** Which existing credential kind and operator-owned configuration path may issue direct model-provider handles for desk mediation and observation calls? The spec prohibits worker-harness credential reuse, but the concrete capability seam must be selected before implementation.
- **NON-BLOCKING — pilot policy.** The first Main policy's exact deadlines, model election, and allowed summarization prompt are org choices. The global-policy mechanism is buildable before this policy is finalized.
- **NON-BLOCKING — escalation topology.** The first authority workers for `ESCALATE` are org choices. Escalation's worker-addressed mechanics are buildable independently.
- **NON-BLOCKING — parent-helper delivery.** `wi_cd2bb06d` owns the `operationalParent` nullability and effective-parent helper. This spec consumes that helper for parent-route escalation and does not duplicate its schema, migration, or implementation.

## Rationale for adding the mechanism

Deleting mediation loses the required delivery guarantee; accepting queue floods as a named failure preserves the present 39-check-in harm. The added mechanism wins because only a durable, worker-addressed mediation seam can reduce interruption while preserving rows and loud failure.
