Decision boundary

A “yes” requires one cold implementer to derive these behaviors from durable public contracts: authenticate; subscribe first; enumerate visible sessions; page transcript history backward; send a message; fetch work items, assignments, attests, and related state; correlate every rebuildable notice to the same public row; survive duplicate, missing, and reordered notices; and rebuild after reconnect without SQLite or an internal serializer.

Observational notices and R8b source invalidations are deliberate exceptions to row correlation: the former are ignored as model state and the latter trigger a declared composed-view refetch. This report does not count either design as a defect.

Exact contract gaps

G1 Transcript rows have no public message-kind discriminator

The REST row freezes role, sender, and content/correlation fields but no messageType. The normative wire schema restricts role to user|assistant. Current product guidance distinguishes model speech, substrate deliveries, and marker messages by an internal sender-plus-first-line convention. A cold client must parse content and reproduce that private convention, directly violating the no-internal-serializer condition.

Exact repair needed: add one closed public field (the named kin proposal is messageType) to the REST R7 row, wire schema, shared message serializer, and message.created payload. It must distinguish at least assistant, substrate, and marker without content parsing.

Blocks: correct bubble/divider/error rendering and preservation of marker semantics.

Evidence: rest-state-api-v1.md:577-590; rest-state-api-v1-wire-schema.md:147-165,178-196; product wire/payloads.ex:10-66.

G2 Sessions are modeled as direct versioned rows but most session mutations have no freshness class

The public session row includes mutable display name, adoption, identity revision, harness/model/effort/context, host, history barrier, state, updated time, mechanical status, and row version. R8 maps only session.spawned and session.retired. There is no session.updated, and sessions have no R9 dependency list for derived mechanicalStatus.

Current main confirms the gap is real: tune mutates session state but declares only message.created; identity apply/repoint also change session projection state without a session class. The A1 verb-table test can pass because it checks declared effects rather than detecting every changed public projection.

Exact repair needed: define a session mutation mapping that emits whenever canonical session bytes or rowVersion change, and either make mechanicalStatus stored/versioned under it or declare the complete R9 dependency set and make sessions a composed view.

Blocks: live session picker names, active/retired state, model/harness badges, host, identity revision, and correct transcript barrier after tune or recovery.

Evidence: rest-state-api-v1.md:589,694-720; event-firehose-v1.md:266-277; product gateway.ex:1138-1140 and org.ex:560-751.

G3 The message-send path is referenced, not specified as one public client contract

The firehose forbids writes on the change socket, then says a chat client sends “through normal gateway verbs (wake)” and M4 says “send via wake.” The three-plane ruling names POST /agent/dispatch as the write door, but the examined contract set does not freeze the device-authenticated wake request body, target fields, acknowledgement, idempotency, or error outcomes. The existing chat socket instead accepts a message frame and dispatches the private post verb.

Exact repair needed: select one Clawline write route and freeze its auth principal, request fields, idempotency key, reply/attachment shape, ack, errors, and correlation to the resulting message.created. If the existing chat socket remains the route, M4/N4 must say so instead of “wake.”

Blocks: sending any message from the same device credential used for REST/firehose, including retry without duplicates.

Evidence: event-firehose-v1.md:151-154,373-377,474-477; rest-vs-cli-adjudication.md:17-29,80-101; product wire/router.ex:140-147,400-451 and wire/socket.ex:439-494.

G4 General REST error wire is not closed

R4 freezes list/detail success envelopes. Status/code behavior is scattered through pagination and authorization clauses. Only ExecutionMap gets an exact error object, JSON key order, headers, and closed code variants. Nothing applies that R4b contract to sessions, messages, work items, assignments, or attests.

Exact repair needed: one general v1 error envelope with status/code mapping, optional fields, content type, caching headers, malformed-query precedence, and identical unknown/forbidden bytes; then state which special resources override it.

Blocks: deterministic auth recovery, invalid-cursor restart, user-visible refusal handling, and forward-compatible decoding.

Evidence: rest-state-api-v1.md:340-388,390-398,921-1051.

G5 REST and transcript authorities disagree on lookup, cursor, projection, and history-barrier semantics

The transcript spec uses case-insensitive substring name lookup, a five-field candidate projection ordered by last activity, message-id cursors, and a 12-key transcript entry that deliberately excludes four client correlation fields. REST uses exact Unicode display-name equality returning complete R7 session rows in (createdAt,sessionKey) order, opaque signed (seq,id) cursors, and a 28-key message row that includes those correlation fields and rowVersion. REST M4/A8 says the CLI wrapper moves to REST and returns the same item shape, but the living CLI surface still points to the transcript spec.

The transcript spec also makes clearedThroughSeq a hard history floor and defines cursor behavior across it. The REST message route exposes the field on session rows but does not state that query floor or the across-barrier cursor behavior.

Exact repair needed: supersede or amend the transcript contract explicitly. Freeze whether REST history applies clearedThroughSeq; freeze the REST-to-CLI cursor translation; and choose one lookup/projection behavior.

Blocks: a thin CLI wrapper, deep scroll across a mid-page engine swap, and any client sharing cursor/cache code with the CLI.

Evidence: transcript-verb-v1.md:72-79,88-125,127-205; rest-state-api-v1.md:390-430,540-590,1055-1088.

G6 Decision-request state and notice vocabulary are not closed over current product states

REST R8 and the firehose registry name opened, ruled, and withdrawn. Current product also emits decision_request.returned, and stored states include answered, consumed, superseded, and returned transitions. The REST wire enum omits returned. A fetched decision can therefore change without a class the spec tells a client to watch, and current-main frames can carry a class/schema value absent from the contract.

Exact repair needed: freeze the complete decision status enum and map every state-changing transition to one R8 class, primary ref, and serializer.

Blocks: live work-state decision banners and correct execution/work refresh after answer, return, consume, or supersede.

Evidence: rest-state-api-v1.md:708; rest-state-api-v1-wire-schema.md:171,194-195; product gateway.ex:780-785, firehose/registry.ex:32-35, and escalation.ex:20,62,610-611,855,1489.

G7 “REST detail equals notice payload” names detail items that have no detail route

R2 exposes only collections for bulk attests and roles; R3 exposes collection-only facts and critical state; messages are nested pages, not addressable message details. Yet A2/A6 repeatedly require every R8 notice payload to equal “the REST detail item.” The shared serializer intent is clear, but the observable comparator is not.

Exact repair needed: either add the missing detail routes (/api/attests/:id, /api/roles/:name, /api/facts/:id, /api/critical-state/:sessionKey, and a message detail form) or redefine A2/A6 as equality to the same resource item returned by any named collection/detail route.

Blocks: executable conformance and single-row recovery; it does not block whole-collection rebuild if the remaining contracts are repaired.

The file is on specs main, but it does not delimit which clauses are r3, r4, candidate, or proposed. What the evidence disproved

“Pagination itself is missing” — disproved

REST fixes tail default, exclusive before/after, oldest-to-newest pages, signed immutable tuples, filter binding, deleted-boundary behavior, and cap 500. The remaining defect is authority/barrier reconciliation, not basic paging.

“Events must replay history” — disproved

Subscribe-first plus buffered LWW notices and a full re-snapshot on any doubt is coherent. Heartbeat seq detects a lost trailing notice. Replay is unnecessary if every displayed state mutation has a mapping.

“Core work/message ids cannot correlate” — disproved in the spec

V5 and REST R8 bind messageId, workItemId, assignmentId, and attestId to the public projection ids. R10 defines version lifetime through delete/recreate. Current-main deviations remain implementation findings.

“Stream assembly must glue chunks” — disproved

The planned model uses finalized message rows and message.created; current public chat payloads declare streaming:false. One stored message is one model row. The closed historical assembly defect does not justify client chunk assembly.

Do not dispatch slice-2 client implementation from the present query/firehose contract. First repair G1-G5 and G8, then re-run this matrix against one exact reviewed three-file revision. G6-G7 and I2-I4 must close before claiming the broader “every admitted shared-state model” goal. I1 can proceed as implementation only after that spec revision is fixed; it is not evidence that the intended REST architecture is wrong.
